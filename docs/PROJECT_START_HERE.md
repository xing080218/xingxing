## 1. 每次开工的执行顺序

1. 读取本文和根目录 `AGENTS.md`，确认当前阶段与不可违反的规则。
2. 查看本次任务涉及的文件，先找已有实现和可复用部分，不凭记忆重写。
3. 判断改动属于界面、状态、数据存取、模型调用、网络服务还是共用工具。
4. 按职责修改；如果目标文件已经过长或承担多类职责，先把本次要改的部分拆清楚。
5. 完成后运行自动测试，并实际检查原有主流程。
6. 如果同一个问题第二次出现，把解决办法提炼成一句可执行规则并更新本文。

文档与用户最新决定冲突时，以用户最新决定为准，并立即修正文档。不要保留两套互相矛盾的规则。

## 2. 当前产品与阶段

濴星语是一个在浏览器中运行的虚拟小手机，核心能力包括：

- 产品显示名固定为“濴星语”；内部 `PocketLab` 存储键属于兼容标识，不随显示名修改。
- 可交互的手机主屏幕和设置页。
- 配置接口地址、API Key、模型名，并执行连接测试。
- 主屏幕不显示 API 状态卡；唯一配置入口是主屏幕的“设置”App。“使用说明”保留一个跳转设置页的入口，并在“粘贴 API Key”步骤说明 Key 只保留在当前浏览器会话、不写入项目文件或日志。
- 多角色聊天：主屏幕“对话”先打开人物列表；人物列表右上角负责添加角色；点击角色进入独立聊天；聊天页保留“编辑角色”。
- 人物列表右上角加号提供“新建角色”和“新建群聊”两个选项；新建群聊把群公告和群聊背景设定放在同一栏中，二者都按文字保存。
- 群聊先完成独立创建、列表展示、编辑和本机持久化；新建群聊可以从现有角色中多选成员，已有群聊可以拉入尚未入群的角色，也可以移出成员。多角色回复和群聊 AI 编排不属于当前阶段，不得用角色聊天数据冒充群聊。
- “对话”列表只显示圆形头像、角色名、相对时间和最新一条消息；最新消息必须单行省略。列表不显示人设、世界书、“当前”徽标、箭头、卡片或阴影。
- 每个角色独立保存名字、人设、头像、聊天记录、聊天背景和 `1–10` 条最大连发消息数；切换角色只读取该角色自己的上下文。
- 群聊使用独立 `groupChats` 数据仓库，稳定字段为 `id`、`name`、`announcement`、`backgroundSetting`、`memberCharacterIds`、`createdAt`、`updatedAt`；群公告、背景设定和成员名单只属于当前群聊，不写入角色、世界书或全局配置。
- 群成员只保存角色稳定编号并按选择顺序排列，同一角色可以加入多个群聊；取消群聊编辑不会保存成员增删，只有点击“创建群聊/保存群聊”才写入本机数据库。
- 主屏幕提供“世界书”App；世界书独立保存、搜索、分类、编辑和删除。一个角色可以绑定一本世界书，多个角色可以共用同一本，但不存在覆盖所有角色的全局世界书。
- 聊天请求只读取当前角色绑定的世界书，并把名称和内容放入该角色的 system prompt；普通聊天消息和未绑定角色不会收到世界书内容。
- 主屏幕最下方用独立毛玻璃 Dock，默认存放“我”App；Dock 最多放 4 个 App，支持与主屏幕双向拖动和 Dock 内左右排序，只显示图标和名称。可保存多份用户本人资料，并指定一份“当前”资料；每个角色可以在角色编辑页选择固定使用哪一份本人资料。角色只保存 `selfProfileId`，未选择、旧角色或原资料已删除时跟随当前资料。本人资料只进入 system prompt，不进入普通聊天消息，也不会写入角色人设或世界书；没有本人资料时聊天请求保持原样。
- 用户可连续发送一条或多条消息，再点“总结并回复”；模型综合理解整组消息，只输出角色要发来的日常聊天内容，不逐条编号作答。
- 最近一轮消息撤回、删除、重新生成。
- 聊天记录保存在本机，刷新后恢复。
- 桌面与移动端布局继续兼容。
- 页面默认先显示锁屏；锁屏底部只显示跳动箭头，不显示“向上滑动解锁”文字或外框。
- 默认开启四位数字锁屏密码，初始密码为 `1234`；向上拖动、点击跳动箭头、按 Enter 或空格后进入密码页，输入满四位自动验证。
- 设置页可以关闭锁屏密码；关闭后上滑直接进入主屏幕，再次开启仍沿用原密码。设置页可更改四位数字密码，修改后刷新页面仍生效。
- 密码页的数字键使用带背景虚化和高光的毛玻璃样式，删除键保持透明图标样式。
- 锁屏密码页不能使用不透明底色覆盖壁纸；密码层只加轻量可读性遮罩，并始终显示当前锁屏背景，包括用户自定义的锁屏图片。
- 主屏幕去掉手机外框，使用奶黄色与冰蓝色搭配。
- 主屏幕应用采用固定四列、固定四行的稀疏网格，共 16 个位置；图标排布按参考图采用大图标、小标签和明显留白，四列占满可用宽度。主屏幕是固定页面，页面和图标区域都不能上下滚动。短按打开 App，长按约 560ms 或电脑右键进入编辑；编辑时显示全部空位。App 可拖到任意空格，原位置留空，拖到已有 App 时两者交换位置。
- Dock 与主屏幕网格共用编辑模式：App 可拖入 Dock、从 Dock 拖回主屏幕，也可在 Dock 内左右排序；Dock 最多 4 个，满额后新增拖动保留原位置，任何情况下不能丢失 App。点“完成”保存，刷新后空位和排列保持。
- 内置默认背景为 `assets/backgrounds/star-cat-planet-default.jpg`，同一张星空猫咪图用于锁屏、主屏幕和聊天页；三处自定义图片分别覆盖对应页面，移除后恢复该内置背景。
- 主屏幕提供“美化”App；“整体手机”包含背景、字体两个子板块，主题板块已移除。
- 美化中的图标布局和聊天外观目前只保留入口与占位说明，本阶段不扩展成完整主题系统。
- 网站使用 `assets/icons/` 中的“星球与双猫”图片作为浏览器图标和手机主屏幕图标；首页同时提供苹果触摸图标与网页应用清单。

## 3. 不可违反的产品规则

### API 与密钥

- 接口地址按服务商文档填写，兼容 OpenAI 格式时统一转换为聊天接口，不在界面中猜造服务商地址。
- API Key 由用户在设置页填写，只临时保存在当前标签页的 `sessionStorage`。
- 代码、文档、测试、日志、截图和 GitHub 文件中只允许出现 `your-api-key` 等占位符。
- 服务端只允许在单次请求的内存中使用 Key，不写日志，不记录请求头，不记录完整请求体。
- 连接失败必须显示真实原因和下一步检查方法，不能只显示“失败”或把所有错误都归因于 Key。
- 成功必须依据模型服务商的有效响应判断。本地健康检查或页面返回 `HTTP 200` 不等于模型接口成功。

### 聊天行为

- 每次发送都携带用户新消息、角色人设和最近的聊天记录。
- 等到模型完整回复后再显示，不显示半截流式文本。
- 模型返回后，按真实换行和句末标点（句号、问号、感叹号等）拆成聊天气泡；只保留角色要发来的消息，去掉空行、编号和格式说明。
- 每条气泡只显示一条消息；整段没有可分句的标点时只显示一个气泡。
- 模型完整回复返回后，聊天气泡按真实聊天节奏逐条出现，不要一次性显示全部；全部气泡出现前继续显示“正在回复”并阻止重复提交。
- 用户可连续发送一条或多条消息，再点击“总结并回复”。模型综合理解整组消息，用日常聊天口吻自然回复，不按第一句、第二句逐条作答。
- 生成中显示“正在回复”，禁用重复提交。
- 失败时保留已经发送的消息，并提供重试入口。
- 撤回和重新生成只作用于允许编辑的最近一轮，删除后立即持久化。

### 当前设备策略

- 电脑和手机统一打开自有正式域名 `https://yingxingyu.com/`，不要求两台设备连接同一个 Wi-Fi。
- 发布前验收统一打开 `https://test.yingxingyu.com/`；功能分支的 Vercel Preview 地址仅供开发检查，不要求用户使用。
- `*.vercel.app` 不是正式入口；它只用于确认 Vercel 部署是否存在，遇到线路拦截时不要让用户改填这个地址。
- 本地 `http://127.0.0.1:4176/` 和手机局域网入口只用于发布前回归或正式网址故障排查。
- 保留现有响应式布局，同一套代码同时服务电脑和手机。
- 除非用户明确要求，不停止、不重启当前正常运行的服务。

## 4. 代码组织规则

每个文件只能有一个主要职责，文件名应直接表达职责。

推荐分层：

| 职责 | 放什么 | 不应放什么 |
| --- | --- | --- |
| 界面 | 页面结构、样式、渲染和交互绑定 | 模型调用、持久化细节 |
| 状态 | 当前会话、角色、消息和生成状态 | DOM 查询、网络请求 |
| 数据存取 | IndexedDB、Blob 图片、轻量设置、数据迁移和校验 | 页面布局、供应商错误文案 |
| 模型调用 | 地址规范化、请求、响应解析和错误分类 | DOM 操作、页面跳转 |
| 网络服务 | 静态文件、API 路由和本机代理 | 前端界面逻辑 |
| 共用工具 | 多个 App 都会使用的纯函数和协议 | 某一个页面专属功能 |
| 测试 | 自动化测试、模拟服务和回归脚本 | 运行时业务入口 |

执行要求：

- 新增功能先复用现有模块；确实需要新模块时，再按单一职责创建。
- 多个 App 共用的密钥存储规则、接口地址处理、错误分类、超时值、版本号和工具函数必须统一维护，禁止复制多份。
- 不把新功能继续追加到已经承担多类职责的大文件中。
- 一个脚本或样式文件超过约 600 行，或开始同时承担两类以上职责时，必须评估拆分。
- 拆分优先按功能边界，不按技术名词机械切割；拆完必须保持原有行为。
- 修改共享模块时检查所有调用方，不能只验证当前页面。
- 数据字段先定义稳定结构再读写。旧数据恢复必须有默认值和容错。

### 本机数据边界

- IndexedDB 是用户数据的唯一持久化来源：`characters` 保存角色，`groupChats` 保存群聊，`messages` 保存聊天，`memories` 保存记忆，`worldBooks` 保存世界书，`appData` 保存各 App 存档，`images` 保存图片 Blob，`meta` 保存迁移状态等内部信息。
- 一个浏览器可以保存多个角色；角色列表按稳定 `id` 管理，当前角色编号只作为轻量设置写入 `localStorage`。
- `messages.characterId` 必须引用现有角色。旧版没有 `characterId` 的聊天统一迁移到 `primary-character`，不得丢失或复制到新角色。
- 每个角色的头像和聊天背景分别只保存 `avatarId`、`chatBackgroundImageId` 图片编号；回复上下文和聊天记录按当前 `characterId` 隔离。
- 角色绑定世界书时只保存 `worldBookId`；一个角色最多绑定一本，多个角色可以共享同一本。删除前必须检查引用，仍被角色使用的世界书不得删除。
- 群聊只保存 `memberCharacterIds` 稳定角色编号，不复制角色资料；成员顺序必须保留并去重，拉入列表只显示尚未入群的角色。
- 用户本人资料保存在 `appData` 的 `self-profiles.v1` 记录中，包含多份资料和唯一 `activeProfileId`；该数据独立于角色人设和世界书。现有备份会随 `appData` 自动包含它，不需要新增备份格式。
- 角色编辑页的本人资料字段只用于选择已保存资料，不提供新增、编辑或删除入口；资料统一在“我”App 管理。角色保存 `selfProfileId`，聊天时优先读取指定资料，指定编号失效时安全回退到当前资料。
- 图片只保存 Blob；角色或其他记录只保存稳定图片编号。显示时生成临时 Object URL，导出或发给 API 等需要序列化的场景再转换格式。
- `localStorage` 只放接口地址、模型名等轻量设置；API Key 和连接状态只放当前标签页的 `sessionStorage`。
- 所有文字记录必须使用稳定 ID。删除或替换记录时先检查引用，不能让角色留下不存在的头像编号。
- 旧 `localStorage` 数据迁移时，先写入 IndexedDB，再验证角色文字、聊天内容和头像 Blob。全部成功后才能删除旧键；任一条无效时整次迁移失败并保留旧键。
- 备份导出包含 `characters`、`groupChats`、`messages`、`memories`、`worldBooks`、`appData`、`images`，当前备份格式为版本 4；图片以 Base64 Data URL 写入 JSON，不包含 API Key。版本 1、2、3、4 均可导入，旧版本缺少群聊数据时按空列表处理，版本 1、2、3 的群聊缺少成员字段时按空数组处理。
- 版本 4 备份中的群成员必须引用同一份备份内存在的角色；任一引用失效时整次导入拒绝，不能写入部分数据。
- 备份导入先在内存中校验全部记录、群聊、世界书引用和图片，再在一个事务中原子替换七类用户数据。导入无效时不得清空现有数据。
- 单张导入图片上限 25 MB，单次备份图片总量上限 100 MB。保存失败或额度不足必须显示在设置页，不能只显示短暂提示。
- 备份和导入开始前，先等待尚未完成的聊天、角色自动保存队列，避免备份漏数据或导入结果随后被旧保存覆盖。
- 美化设置保存在 `appData` 的 `beautify.settings.v1`；全局背景、锁屏背景、聊天背景分别只引用 `beautify-home-wallpaper`、`beautify-lock-wallpaper`、`beautify-chat-wallpaper` 三个 Blob 图片 ID，不把图片内容写入设置记录。
- 主屏幕与 Dock 排列保存在 `appData` 的 `home-screen.layout.v1`。版本 4 使用固定四列的 `homeSlots` 稀疏数组保存主屏幕位置，`null` 代表空位，并用 `dockOrder` 保存 Dock；主屏幕固定 16 格，不能增减或滚动。旧版 12 格、20 格布局、`order`、`homeOrder` 与 `dockOrder` 自动迁移：前 16 格保留原位置，旧第五排等超出范围的 App 依原顺序补进第一个空位，忽略未知和重复编号。
- 每个 App 必须且只能位于主屏幕或 Dock 一处；Dock 上限固定为 4 个，超出项安全移回主屏幕。长按、拖动或右键结束后必须抑制随后触发的普通点击，避免编辑时误开 App。
- 锁屏、主屏幕和聊天页未设置自定义图片时显示同一张内置默认背景；该默认图属于静态项目资源，不占用用户图片存储。
- 锁屏密码只保存启用状态和自定义密码的摘要（`localStorage` 键为 `pocket-lab-lock-password-enabled`、`pocket-lab-lock-password-hash`），不保存明文密码；初始密码 `1234` 由代码提供，仅用于首次使用。
- 美化字号范围固定为全局 `12–20px`、聊天气泡 `11–24px`；拖动时预览立即生效，松手立即落盘，刷新后恢复。
- 全局背景只作用于主屏幕，锁屏背景只作用于锁屏，聊天背景只作用于聊天页；三个入口互不覆盖。
- 浏览器端回归脚本每次 `Page.navigate` 或 `Page.reload` 后都要先调用锁屏解锁辅助函数，再继续点击主屏幕或聊天入口。

## 6. 反复问题的简短规则

### 连接排查先分段

- 先区分“浏览器到本机服务”和“本机服务到模型服务商”。
- 本地页面能打开、健康接口返回 200，只能证明第一段正常，不能证明 API 配置成功。
- `EACCES`、`ECONNRESET`、Schannel、加密连接中断通常发生在请求到达服务商之前，不要先让用户重填 Key。
- 接口返回 HTTP 状态时，显示真实状态和上游原因，不用 `OK` 代替错误状态。

### 超时语义

- 模型请求默认最多等待约 120 秒，本机代理约 130 秒，浏览器约 140 秒。
- 真实超时统一返回 `HTTP 504` 和 `error.code = timeout`。
- 不要把超时显示成 `HTTP 200`，也不要把边界超时误判为 `connection_reset`。

### 页面白屏与缓存

- 修改网页脚本、样式或入口后更新版本号，并确认 HTML 引用了新版本。
- 白屏排查先看纯文字检查页和健康接口，再查主页面脚本错误。
- 服务端静态资源使用 `no-store`，避免电脑或手机继续加载旧文件。

### 本机服务

- 当前电脑入口固定为 `http://127.0.0.1:4176/`。
- 启动窗口关闭后服务会停止；需要重新启动时使用项目内的启动脚本。
- 服务已经在运行时，不为同一问题反复重启；先用健康接口确认状态。

### 角色切换与保存

- 角色保存、切换期间必须统一锁定聊天交互；保存或切换结束后在 `finally` 中解除锁定并刷新发送、批量回复和人物列表添加按钮状态，避免旧角色输入框或发送按钮长期禁用。
- 切换角色时必须等待当前角色的消息保存队列完成，并在加载目标角色记录后再恢复交互，防止消息保存到错误角色。

### 群聊成员

- 新建群聊和已有群聊共用成员草稿：选择、拉入、移出只改当前弹窗，点击取消必须完全丢弃，点击保存后才写入 IndexedDB。
- 群聊只保存 `memberCharacterIds` 稳定角色编号并保留选择顺序；已有成员不重复出现在“拉入角色”列表，取消或保存后都按数据库实际结果重新渲染。

### 对话列表

- “对话”列表只显示头像、角色名、时间和最新一条消息；不得重新加入人设、世界书、当前徽标或箭头。
- 最新消息取最后一条未撤回且内容非空的用户或角色消息，合并换行和连续空白后严格单行省略；列表按最新消息时间倒序，没有消息的角色保持原顺序。
- 人物列表右上角“添加角色”按钮使用参考图配色：背景 `#DCFEFF`、边框 `#D5F3F3`、加号 `#80C9D7`；只调整颜色，不改变按钮尺寸或位置。
- 人物列表条目保持紧凑：头像 `52px`，桌面行高至少 `76px`、手机行高至少 `78px`，名称 `15px`、预览 `13px`；不要压缩到低于常用触控尺寸。
- 人物列表右上角加号必须同时提供“新建角色”和“新建群聊”；群聊条目使用独立群组图标，预览依次取群公告、群聊背景设定、默认提示，点击进入群聊编辑。

### 主屏幕拖动与比例

- 稀疏主屏幕拖动期间只更新目标容器和目标格高亮，不在途经图标时即时换位；松手后按最终目标一次计算并保存，避免拖动经过其他 App 时连续交换。
- 主屏幕始终保持四列四行、固定 16 格；普通模式隐藏空位，编辑模式显示全部空位，页面和图标区域都不滚动。迁移旧布局时必须把超出 16 格的 App 补进前 16 格空位，不能丢失。手机、窄屏和横屏都必须让四行完整落在屏幕内，同时设置图标宽高并实际检查为正方形，不能用单独的 `flex-basis` 代替高度。
- 图标排版按参考图保持“单列全宽、图标约为列宽 60%、标签约为图标两成高”的比例；优先保证四行完整和拖动命中区，横屏可压缩标签间距但不能滚动或重叠。

### 小手机顶部与系统安全区

- 网页小手机顶部不再绘制仿制灵动岛或额外黑色药丸；保留时间、信号、Wi-Fi、电池和系统安全区内边距。
- 主屏幕不显示“常用功能”标题；日期位于顶部状态栏时间右侧，仅显示在已解锁的主屏幕，其他页面和编辑主屏幕时隐藏。
- iPhone 截图最上方的灵动岛属于手机系统界面，网页无法移除；用户要求去掉顶部黑色长条时，只删除网页自己绘制的那一条。

### Vercel 自动发布

- 分支固定为 `feature/* -> test -> main`。功能分支只供开发检查，用户验收使用 `test`，用户明确确认后才允许进入 `main`。
- Vercel Production Branch 必须设为 `main`，测试域名必须绑定 `test`，Git 集成必须保持启用。
- GitHub `main` 和 `test` 用分支保护强制走合并请求；不要为了绕过保护而临时关闭规则。
- 正式项目为 `xingxing`，正式网址为 `https://yingxingyu.com/`；项目保持公开访问，不启用 SSO 或密码保护，除非用户明确要求。
- 测试网址为 `https://test.yingxingyu.com/`；对应分支为 `test`，DNS 和 HTTPS 已启用。每次合并后先等待 Vercel 部署完成，再用真实浏览器分别检查电脑和手机尺寸。
- 本机 PowerShell、Windows `curl` 或 Node 出现证书/Schannel 错误时，先改用无头 Chrome 访问测试网址；Chrome 能加载页面且后续改动会触发 Vercel 部署时，不为本机工具错误重配 DNS。
- 自有域名的根域名使用阿里云 A 记录指向 Vercel，`www` 使用 CNAME；根域名是当前唯一正式入口，`www` 未完成稳定验证前不要发给用户。
- 若中国大陆网络把 `vercel.app` 域名解析到异常地址，先确认 DNS 结果；`yingxingyu.com` 已作为长期入口，不能把错误 IP 写进代码。
- `xingxing-tan.vercel.app` 超时但外部检查为 `Ready` 且健康接口返回 200 时，判断为用户网络到 `vercel.app` 的线路或域名拦截，不要反复重新部署；临时测试可用 Cloudflare Quick Tunnel 指向本机 `http://127.0.0.1:4176`，必须明确它依赖本机服务和隧道进程，永久访问使用 `https://yingxingyu.com/`。
- 云函数总等待时间受 Vercel 时限限制；模型请求最多等待 50 秒，接口函数上限设为 60 秒。
- 线上失败先检查 `/api/health` 的 `mode` 是否为 `vercel`，再区分 Vercel 到模型服务商与用户浏览器到 Vercel 两段。
- API Key 只随当前请求进入云函数内存；日志、GitHub、文档和测试只允许使用占位符。

### PowerShell 读写

- 本项目文件使用 UTF-8。用 PowerShell 查看中文文件时显式加 `-Encoding UTF8`，避免把正常中文误判成乱码。
- Windows PowerShell 5.1 执行的含中文脚本应保存为“UTF-8 带 BOM”；无 BOM 时解析器可能按系统编码误读并报出与实际代码无关的语法错误。
- PowerShell 严格模式下不能直接读取 `ConvertFrom-Json` 结果里的可选字段；统一通过 `PSObject.Properties` 安全读取，并用空配置回归测试确认返回 400 和检查建议。
- 手工代码修改使用补丁工具；批量格式化或机械拆分后再运行语法检查。
