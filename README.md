# 濴星语 · 单角色对话

濴星语是一个在浏览器里运行的虚拟小手机。当前版本包含可交互的主屏幕、API 设置页、连接测试、单角色聊天、连续留言和本机转发服务。

> 开工前先读：[`docs/PROJECT_START_HERE.md`](docs/PROJECT_START_HERE.md)。Codex 会先读取根目录 `AGENTS.md`，再由它指向这份统一规则。

## 当前阶段

- 支持本地运行，也支持部署到 Vercel，由电脑和手机直接打开正式网址。
- 本地入口仍为 `http://127.0.0.1:4176/`，适合在发布前检查改动。
- GitHub 的 `main` 分支是正式发布来源；推送到该分支后，Vercel 会自动重新发布。

## 打开方式

1. 双击 `start.bat` 一次，浏览器会自动打开电脑地址；如果没有自动打开，请手动访问 `http://127.0.0.1:4176/`。
2. 测试期间请保留启动窗口，不要关闭。

以下手机局域网步骤只作为正式网址无法访问时的本地备用方案：

3. 第一次尝试手机局域网访问时，先双击 `enable-phone-access.bat`，并在 Windows 管理员提示中选择“是”。
4. 手机与电脑连接同一个 Wi-Fi 后，在电脑打开 `http://127.0.0.1:4176/connect.html`。入口页会自动读取电脑当前的 Wi-Fi 地址，并显示手机应该打开的两个地址。
5. 在手机浏览器输入入口页显示的“手机打开濴星语”地址。地址必须以 `http://` 开头，不要使用旧二维码、旧 IP、`127.0.0.1` 或 `localhost`。
6. 如果电脑网址打不开，再双击 `start.bat` 一次。已有服务会被替换为当前代码，不会重复占用端口。

手机浏览器打不开主页面时，先打开纯文字检查页。必须输入完整的 `http://`，不能输入 `https://`、`127.0.0.1` 或 `localhost`：

```text
http://电脑局域网地址:4176/mobile-check.html?v=20261120-22
```

入口页会自动显示当前可用的局域网地址，不需要手动猜 IP。能看到“已连接到当前电脑服务，版本 20261120-22”说明本地网络和当前服务都已通；如果仍然打不开，请检查 iPhone 的“设置 → 隐私与安全性 → 本地网络”是否允许 Safari，以及路由器是否开启了 AP 隔离或访客网络。

如果检查页能打开、主页面仍然白屏，请改用检查页里的“打开濴星语”链接。该链接带有新版本号，可以避开 Safari 的旧页面缓存。仍然白屏时，完全关闭 Safari 标签页后重新打开检查页。

如果检查页能打开，但页面里的状态检查显示超时，说明“手机 → 电脑”的网页请求已经成功，超时发生在同一台电脑上的第二次状态请求。请先刷新检查页，或直接从检查页打开濴星语；不要先改 API Key。

## 手机和电脑使用

- 电脑和手机都直接打开正式网址：https://xingxing-tan.vercel.app/
- 手机和电脑不需要连接同一个 Wi-Fi；本地启动窗口关闭后，正式网址仍可继续使用。
- 如果正式网址打不开，再按上方局域网备用步骤检查本机页面和网络。
- 手机页面会铺满屏幕，并适配触屏输入、手机安全区、底部键盘和刘海屏；电脑页面显示固定尺寸的手机外框。
- 手机和电脑各自保存自己的聊天记录；聊天记录不会在不同设备之间自动同步。

## 单角色聊天

1. 连接测试成功后，回到主屏幕打开“对话”。
2. 点右上角的编辑按钮，填写角色名字、人设，并按需选择头像。
3. 在底部输入消息并发送。模型完整返回后，回复会按真实换行拆成多个气泡，空行不会显示。
4. 角色资料和聊天记录保存在本机浏览器中，刷新页面后仍会保留。
5. 如果请求失败，已发送的消息会保留；在失败卡片下方点“重试”即可再次请求。

每次发送都会把角色人设、角色名字、最近 20 条成功聊天记录和当前消息一起交给模型。聊天记录不会写入项目文件。

## 本机存储与备份

- 角色、聊天、记忆、各 App 存档和图片统一保存在浏览器的 IndexedDB。
- 头像等上传图片以 Blob 保存；角色和其他文字记录只保存稳定的 `avatarId` 或图片编号，显示时再转换为临时预览地址。
- API 地址和模型名属于轻量设置，保存在 `localStorage`；API Key 只保存在当前标签页的 `sessionStorage`，关闭标签页后清除。
- 旧版 `localStorage` 角色与聊天数据会在页面启动时迁移。程序先把文字、聊天和旧头像写入 IndexedDB，再读回验证；只有全部验证成功后才删除旧记录。任何一条数据无效时，整次迁移停止并保留旧记录。
- 设置页的“导出备份”会生成一个包含角色、聊天、记忆、App 存档和图片的 JSON 文件。图片会在导出时转换为 Base64，便于放进单个文件。
- “导入备份”会先校验全部文字和图片，再在一个数据库事务里整体替换五类用户数据。任何一条无效时不会清空或修改现有数据。
- 备份不包含 API Key。单张导入图片不能超过 25 MB，备份内图片总量不能超过 100 MB。
- 保存失败、数据库被阻止或空间不足时，设置页“本机数据”区域会显示原因和下一步检查方法。

### 连续留言

1. 在聊天输入框上方点“连续留言”，按钮进入选中状态。
2. 连续输入并发送多条想说的话。这时消息会先排队，不会立刻请求模型。
3. 检查右侧显示的待回复条数，然后点“统一回复”。
4. 模型会一次收到这组留言，并按编号顺序逐条回答；每条回答会显示为独立气泡。
5. 请求失败时，整组留言会保留。点“重新统一回复”即可重试，不会重复添加留言。

每组最多 20 条留言。连续留言等待回复时，刷新页面仍会恢复待回复状态。

### 撤回与重新生成

1. 每条最新一轮消息下方都有一个 `…` 按钮。点开后可以撤回自己的消息，或删除角色的回复。
2. 只想换一个回答时，点角色回复下方的 `…`，选择“删除回复”。原来的提问会保留，随后点“重新生成回复”即可。
3. 想连同这次提问一起撤回时，点任意一条消息下方的 `…`，选择“撤回本轮”。这一轮的用户消息和角色回复会先收起。
4. 撤回后可以点“重新生成本轮”，也可以点“彻底删除”。撤回状态会保存在本机，刷新后仍能恢复。

为了避免影响后面的聊天上下文，目前消息操作只用于最近一轮对话；彻底删除后无法恢复。

## “本机网络权限阻止了连接（EACCES）”怎么处理

这条提示表示 Windows 在本机建立连接时阻止了程序，请求还没有到达服务商，因此通常不是 API Key、模型名或接口地址填写错误。

当前版本会启动本机网页服务和独立的 Node.js 网络传输。测试期间请保留启动窗口；如果窗口关闭后网页打不开，重新双击 `start.bat`。

1. 确认启动窗口正在运行，并记录其中的电脑和手机地址。
2. 如果电脑或手机打开的是旧页面，先完全关闭旧标签页，再双击一次 `start.bat` 让启动器替换当前服务；测试期间不要关闭正在使用的启动窗口。
3. 检查 Windows 安全中心、防火墙、VPN、代理或安全软件，确保没有阻止 PowerShell 和 Node.js 访问“专用网络”或外网。
4. 回到设置页重新点“连接测试”。失败卡片会直接显示原因和下一步检查方法；不要把真实 API Key 发到聊天、截图或日志中。

## “连接超时 · HTTP 504”怎么处理

当前版本最多等待模型服务商约 120 秒。`HTTP 504` 是电脑上的本地服务返回的“等待超时”，不是模型服务商返回了 504，也不代表 API Key 或模型名一定填写错误。手机能看到濴星语页面，说明“手机 → 电脑”这一段已经连通；失败发生在“电脑 → 模型服务商”这一段。

1. 双击 `enable-phone-access.bat`，在 Windows 管理员提示中选择“是”。
2. 脚本会解除本机出站拦截，并重新创建只允许同一局域网访问 `4176` 端口的入站规则。
3. 双击 `start.bat`，不要使用旧的黑色窗口或旧网址。
4. 重新打开设置页，等页面加载完成后只点一次“连接测试”，并给它约 120 秒完成。
5. 如果仍超时，关闭 VPN、代理和安全软件的网络拦截；路由器还需要关闭 AP 隔离或客户端隔离。
6. 推理模型可能在长时间思考后仍不返回文字，请先换用普通对话模型测试。

## “安全包中没有可用的凭证”怎么处理

这条提示表示请求曾经过 Windows 自带的 Schannel HTTPS 组件，而该组件没有拿到可用凭证。它发生在请求到达服务商之前，因此不是 API Key、模型名或接口内容错误。

当前版本已经移除 Windows `curl.exe`/Schannel 兼容回退，正常请求只使用随应用运行的 Node/OpenSSL。更新代码后重新双击 `start.bat`，启动器会替换旧服务；只刷新浏览器不会重新载入本机连接模块。测试期间保留启动窗口。

1. 如果使用的是旧版本，直接重新双击 `start.bat`；启动器会替换旧服务。测试期间保留当前启动窗口。
2. 等启动器显示 `小手机已经在后台启动`，使用新窗口显示的地址重新打开小手机。
3. 再点一次“连接测试”。连接正常时，设置页会显示 HTTP 状态、模型名和耗时。
4. 如果新版本仍显示同类错误，检查 VPN、代理、公司网络或安全软件是否拦截了本机程序；不要把真实 API Key 发到聊天或日志中。

## “HTTPS 加密连接被中断（ECONNRESET）”怎么处理

这类错误发生在请求到达服务商之前，通常不是 API Key、模型名或接口地址内容错误。常见原因是 Radmin VPN、其他虚拟网卡、代理或当前网络线路中断了 TLS 握手。

当前版本会依次尝试普通连接、TLS 1.2 兼容连接，以及固定从正常的 Wi-Fi/以太网网卡发出请求。第三次重试会避开名称中含 Radmin、VPN、TAP、TUN、Hyper-V 等虚拟网卡。

看到这个错误时，先区分两段连接：

1. 手机能打开濴星语页面，说明“手机 → 电脑”已经正常。
2. “连接测试”失败说明“电脑 → 模型服务商”没有完成，此时不要重新填写 API Key。
3. 退出 Radmin VPN、其他 VPN、代理和安全软件的网络拦截，刷新页面后只点一次“连接测试”，等待自动重试全部结束。
4. 如果仍然失败，把电脑 Wi-Fi 切换到手机热点后再测试。
5. 接口地址应保留服务商文档中的域名，不要把域名换成错误信息里的远端 IP。

## “模型输出预算不足”怎么处理

这条提示表示服务商已经收到请求，也不是 API Key 或接口地址错误；真正的原因是模型的思考过程先耗尽了输出额度，还没生成答案就被截断了。当前连接测试不会再发送很小的 `max_tokens` 上限。如果服务商仍返回这条信息：

1. 在服务商控制台或网关中提高 `max_output_tokens` 或 `thinking budget`。
2. 如果当前使用的是推理模型，可以先换用普通对话模型测试。
3. 修改后重新点“连接测试”。

## 接口格式

当前版本按 OpenAI 兼容协议请求：

```text
POST {接口地址}/chat/completions
Authorization: Bearer {API Key}
```

接口地址可以填写以下任一种形式：

- Base URL，例如 `https://api.example.com/v1`
- OpenAI 兼容 API 根地址，例如 `https://api.example.com`
- 完整地址，例如 `https://api.example.com/v1/chat/completions`

如果服务商使用 Anthropic、Gemini 或其他非 OpenAI 兼容协议，需要根据该服务商文档增加专用适配。

## 安全约定

- 仓库中只出现 `https://api.example.com/v1`、`your-model-name` 等占位内容。
- API Key 只保存在当前标签页的 `sessionStorage` 中，关闭标签页即清除。
- 默认允许同一局域网内的设备打开页面；本机服务不会保存 API Key。
- 服务端日志只记录成功/失败状态，不记录 API Key、请求头或请求体。
- 本机转发服务需要按键请求服务商，API Key 会短暂经过本机进程内存。
